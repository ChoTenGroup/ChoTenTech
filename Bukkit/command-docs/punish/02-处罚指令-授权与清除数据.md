# 处罚指令：授权（AUTH 验证）与清除数据（WIPE）

> **根指令**：`/chotentech-authpunish`（别名 `cttauth`、`authpunish`）、`/chotentech-wipe`（别名 `cttwipe`、`wipe`）、`/chotentech-resumewipe`（别名 `cttresumewipe`、`resumewipe`）
> **权限**：见下表；三个根指令均为 `permissionDefault = PermissionDefault.OP`，且声明 `newParser = false`
> **源码**：`Bukkit/src/main/kotlin/io/github/zzzyyylllty/chotentech/punish/PunishCommand.kt`（第 290–466 行，三个 `@CommandHeader` 对象）

## 功能概述

本文件涵盖处罚系统里两条「非常规」处罚与一条配套的撤销指令：

- **`/chotentech-authpunish`**：单独签发一条 `PunishType.AUTH`（身份验证）记录，效果与「带 AUTH 的封禁」相同——玩家在 `PlayerLoginEvent` 阶段被拦下，必须联系管理员解除。
- **`/chotentech-wipe`**：清除玩家数据（整包 / 物品栏 / 指定货币），**清除前先把数据快照备份进数据库**，返回一个处罚 ID。
- **`/chotentech-resumewipe`**：用上一步返回的处罚 ID 把备份还原回去（撤销清除）。

`authpunish` 与 `wipe` 的指令结构是 `mainCommand { dynamic("target") { … } }`：只有一个真正的参数 `target`，其余内容在 `execute` 的 `argument`（剩余文本）里解析。
`resumewipe` 的结构是 `mainCommand { int("punishment_id") { … } }`：唯一参数是整数型的处罚 ID。

> 三个根指令都**没有**给 `mainCommand` 挂 `execute` / `createModernHelper()`，无参执行不会打印帮助树。

## 指令总览

| 根指令 | 别名 | 说明 | 权限 | 默认 |
|---|---|---|---|---|
| `chotentech-authpunish` | `cttauth`、`authpunish` | 签发 AUTH 身份验证处罚（限制登录，需管理员解除） | `chotentech.command.authpunish` | OP |
| `chotentech-wipe` | `cttwipe`、`wipe` | 清除玩家数据（`all` / `inventory` / 货币 ID），并自动备份 | `chotentech.command.wipe` | OP |
| `chotentech-resumewipe` | `cttresumewipe`、`resumewipe` | 用处罚 ID 还原被清除的数据 | `chotentech.command.resumewipe` | OP |

## 指令详解

### `/chotentech-authpunish <target> [-s] [<时长>] [<理由>]`

- **用途**：要求某玩家通过「身份验证」——实际效果是**禁止其登录**，直到管理员解除该 AUTH 处罚。`/ban` 在不带 `-n` 时会自动签发一条这样的记录（永久）。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `target` | 目标玩家：在线玩家名 / UUID / 数据库中登记过的玩家名（源码 `dynamic("target")`） | 必填 | 自动补全：当前在线玩家名 |
  | `-s` | 静默标志，可重复，需写在剩余文本最前面（`parseAuthArgs` 循环剥离） | 可选 | 无 |
  | `<时长>` | 时长 token（如 `30m`、`7d`、`1d12h`）或 `永久`/`perm`/`permanent`/`forever`/`-1`；**不给 = 永久** | 可选 | 无 |
  | `<理由>` | 理由，剩余整段文本；留空时用默认值 `需要进行身份验证` | 可选 | 无 |

- **权限**：`chotentech.command.authpunish`（默认 OP）；`execute` 内无额外 `hasPermission` 校验，**且不经过 `punishment.duration-limits` 的时长裁剪**（源码没有调用 `getMaxDuration`）。
- **执行者要求**：玩家 / 控制台均可（`execute<CommandSender>`）；目标必须能被解析到，否则 `未找到玩家: <输入>`。
- **行为说明**：
  1. `parseAuthArgs`：先剥离 `-s`；剩余为空 → `durationMs = -1`（永久）；否则按「永久 / 时长 token」解析，解析不出时长（0）时同样回落为 `-1`（永久）。
  2. 理由为空 → `需要进行身份验证`。
  3. 写入 `type = AUTH` 记录，`silent` 字段会被写进记录，但**本指令根本不发全服公告**，所以 `-s` 实际上不改变任何可见行为。
  4. 执行者收到 `已对 <玩家> 添加AUTH验证，时长: <X>，ID: <id>`。
  5. 目标在线 → 立即被踢，提示为三行：
     `你被要求进行身份验证！` / `理由: <理由>` / `时长: <X>` / `请主动联系管理员解除`。
  6. 之后玩家再登录时由 `PunishListener.onLoginBanCheck`（`isBannedOrAuthLocked`）拦截，提示 `你已被身份验证！…请主动联系管理员解除验证`，非永久时还会显示 `解封时间: yyyy-MM-dd HH:mm:ss`。
  7. 到期后（若设了时长）由每 10 秒的到期扫描自动解除，并给在线玩家发 `你的身份验证处罚已到期。`
- **示例**：
  - `/cttauth Steve 永久 疑似盗号` → 永久 AUTH 验证。
  - `/authpunish Steve 2h 需要人工核验` → 2 小时后自动解除。

### `/chotentech-wipe <target> <作用域> [<理由>]`

- **用途**：清除玩家数据（物品栏 / 末影箱 / 指定货币），**清除前自动快照备份**，并返回一个处罚 ID 供 `/chotentech-resumewipe` 还原。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `target` | 目标玩家：在线玩家名 / UUID / 数据库中登记过的玩家名（源码 `dynamic("target")`） | 必填 | 自动补全：在线玩家名（与下面 5 个关键字混在同一个补全列表里） |
  | `作用域` | 剩余文本的**第一个词**（`parseWipeArgs` 用 `split("\\s+", 2)` 切分）。可用逗号组合多个：`inventory,MEG`。见下方「作用域取值」 | 必填 | 补全列表为 `all`、`inventory`、`MEG`、`BNTG`、`UEC`（源码把关键字和在线玩家名拼在同一个 `suggestion` 里） |
  | `<理由>` | 第一个空白之后的所有文本；留空时用默认值 `违反服务器规则` | 可选 | 无 |

  **作用域取值**（判断在 `PunishManager.captureWipeSnapshot` / `clearWipedData` 内，先按逗号拆分并 `trim().lowercase()`）：

  | 作用域 | 清除内容 |
  |---|---|
  | `all` | 快捷方式，等价于「物品栏 + 末影箱 + 货币 `MEG`/`BNTG`/`UEC`」 |
  | `inventory` | 主物品栏 + 末影箱（两者一起） |
  | 其它任意字符串 | 当作**货币 ID**，到 `currency.yml` 里查（见「备注」第 3 条），把该货币余额清零 |

- **权限**：`chotentech.command.wipe`（默认 OP）；无运行期额外校验。
- **执行者要求**：玩家 / 控制台均可。**目标可以离线**，但离线时不会立刻清除（见行为说明第 5 条）。
- **行为说明**：
  1. `parseWipeArgs` 把剩余文本切成两段：`scope` = 第一段，`reason` = 第二段（可含空格）。
  2. 若 `scope` 为空（即 `/wipe <玩家>` 后面什么都没写）→ 输出两条错误提示并结束：
     `请指定清除范围: all / inventory / 货币ID(如MEG,BNTG)`、`用法: /wipe <玩家> <作用域> [理由]`。
  3. 目标在线 → `captureWipeSnapshot(player, scope)` 抓取快照（物品栏、末影箱、按作用域抓取的货币余额）；目标离线 → 使用**空快照** `WipeSnapshot()`。
  4. 写入 `type = WIPE` 记录（`durationMs = 0`，`meta["scope"] = <原样作用域>`），拿到 `ID`；随后把快照作为 `WipeBackupEntry`（`punishmentId = 该 ID`、`scope`、`dataJson`、`backupTime`）插入 `wipe_backups` 表。
  5. 目标在线 → 立刻 `clearWipedData(player, scope)` 执行清除，并通知玩家 `你的数据已被管理员清除！范围: <scope>，理由: <理由>`。
     目标离线 → 只回执行者 `玩家离线，物品栏数据将在下次上线时清除。备份已保存。`（补执行依赖 `PunishListener.onJoinExecuteOfflineWipe`，它只挑出「备份 JSON 仍等于 `{}`」的 WIPE 记录来补执行——见「备注」第 5 条的时限问题）。
  6. 执行者最后收到两条提示：`已清除 <玩家> 的数据，范围: <scope>，ID: <id>` 与 `备份已保存。可使用 /resumewipe <id> 还原`。
  7. **不清除**「玩家数据」中的其它字段：`WipeSnapshot.playerDataFields` 虽然定义了，但 `captureWipeSnapshot` 永远返回空表，源码也没有任何按字段清除的逻辑。
- **示例**：
  - `/wipe Steve all 使用外挂` → 清空物品栏 + 末影箱 + `MEG`/`BNTG`/`UEC` 三种货币，并备份。
  - `/wipe Steve inventory 违规物品` → 只清物品栏与末影箱。
  - `/cttwipe Steve MEG,BNTG 刷货币` → 只清这两种货币的余额。
  - 撤销：`/resumewipe 123`（123 为上一步输出里的 ID）。

### `/chotentech-resumewipe <punishment_id>`

- **用途**：把某次 `/wipe` 清除的数据从备份还原回去（撤销清除）。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `punishment_id` | 整数处罚 ID，即 `/wipe` 执行完输出的 `ID: <数字>`，也就是 `wipe_backups.punishmentId` | 必填 | 源码 `suggestion` 返回空列表（**没有**任何 Tab 补全） |

  该参数由 TabooLib 的 `int("punishment_id")` 声明，必须是整数；`execute` 内再用 `toLongOrNull()` 兜底，`≤ 0` 或非法时提示 `请输入有效的处罚ID`。
- **权限**：`chotentech.command.resumewipe`（默认 OP）；无运行期额外校验。
- **执行者要求**：玩家 / 控制台均可。**但物品还原只对在线玩家生效**（见「备注」第 4 条）。
- **行为说明**：
  1. `PunishManager.restoreWipe(id, operatorName, operatorUuid)`：
     - `getWipeBackup(id)` 按 `punishment_id` 查 `wipe_backups`；查不到 → 返回 false。
     - 反序列化 `dataJson` 为 `WipeSnapshot`；失败或为空 → 返回 false。
     - 目标在线时才还原：物品栏（按 `inventory.addItem` 逐个放入，**放不下的先塞末影箱，仍未放下的掉落在玩家脚下**，并提示 `物品栏已满，部分还原物品已放入末影箱或掉落在地上`）；末影箱按槽位 `setItem` 还原。
     - 调用 `deactivatePunishment(id)` 把该条 WIPE 处罚置为非激活。
     - 把该备份行的 `dataJson` 覆盖写成 `{"restored":true}`（备份内容被丢弃）。
  2. 成功 → `已还原处罚 ID: <id> 的数据`；失败 → `未找到处罚 ID: <id> 的备份数据，或还原失败`。
  3. **不会还原货币余额**：快照里虽然存了 `currencies`，`restoreWipe` 只处理 `inventory` 与 `enderChest`。
- **示例**：`/resumewipe 123`、`/cttresumewipe 123`。

## 备注 / 注意事项

### 1. 时长格式（`authpunish` 用到）

与 `/ban` 相同，见 `01-处罚指令-禁言踢出警告封禁.md`「备注」第 1 条，要点复述：

- 单位：`s` 秒、`m` 分、`h` 时、`d` 天、`w` 周（7 天）、`M`/`mo` 月（按 30 天）；可串联（`1d12h`）；数字与单位之间可带空格。
- 永久写法：`永久`、`perm`、`permanent`、`forever`、`-1`。
- `authpunish` **不套用** `punishment.duration-limits` 的权限时长上限（源码未调用 `getMaxDuration`），权限够就能设任意长/永久。

### 2. 数据存储与相关表

| 内容 | 位置 |
|---|---|
| 处罚记录（含 AUTH / WIPE 条目） | 表 `punishment_records`（`id`、`targetUuid`、`type`、`reason`、`durationMs`、`issueTime`、`expiryTime`、`active`、`silent`、`metaJson` 等） |
| 清除数据备份 | 表 `wipe_backups`（`punishmentId`、`targetUuid`、`targetName`、`scope`、`dataJson`、`backupTime`），**没有** `@Id`，走自增主键 |
| 处罚历史 | 插件目录 `punishment_history.json`（每次 `issue()` 追加一行 JSON） |
| 数据库连接 | `PunishManager` 用 TabooLib `db("config.yml", "database", "chotentech.db")`；连接参数取自 `config.yml` 的 `database` 段（内置默认 `enable: false` = SQLite，`true` = MySQL） |
| 内存缓存 | `PunishManager.activeCache`（登录拦截/禁言判断读它；启动时 `reloadActiveCache()` 从库回填未过期记录） |

- 备份数据里物品栏/末影箱是 `ItemStack[]` 的 JSON（只序列化非 `null` 槽位，因此**空槽位位置会丢失**，还原时按顺序 `addItem`）。

### 3. 货币 ID 的实际含义（`wipe` 的「其它作用域」）

- 作用域里的货币 ID 会被 `clearWipedData`/`captureWipeSnapshot` **转成小写**后交给 `CurrencyUtil`，而 `CurrencyUtil` 是按 `currency.yml` 的**顶层键名**精确查表的（大小写敏感），查不到时余额返回 `0.0`、扣除直接返回 false。
- 插件内置的 `currency.yml` 只定义了：`money`、`point`、`tape`、`ltoken`、`ptoken`（`type: PLUGIN`，走插件自带经济 `CurrencyManager`）。也支持 `type: PAPI` + `actions.remove` 的 Kether 脚本扣除方式。
- 因此源码里示例/补全写的 `MEG`、`BNTG`、`UEC` **只有在服务器自己的 `currency.yml` 里确实存在这些小写键（`meg`/`bntg`/`uec` 或对应键）时才有意义**；否则：
  - 显式写 `/wipe <玩家> MEG` → 转小写后查表失败 → 余额读成 0、扣除无效（不会有任何报错）；
  - 写 `/wipe <玩家> all` → `captureAllCurrencies`/`clearWipedData` 的 `all` 分支**固定用大写** `MEG`/`BNTG`/`UEC` 直接查表，同样依赖 `currency.yml` 里存在同名键。
- 结论：管理员应先核对 `plugins/ChoTenTech/currency.yml` 的实际键名，再决定 wipe 的作用域写法。

### 4. ⚠️ 还原（`/resumewipe`）的重要限制

1. **必须在玩家在线时还原**：`restoreWipe` 只有在 `Bukkit.getPlayer(uuid) != null` 时才会往物品栏/末影箱里放东西；但无论玩家是否在线，它都会 `deactivatePunishment(id)` 并把备份 `dataJson` 覆盖成 `{"restored":true}`。
   ⇒ 对离线玩家执行 `/resumewipe` **会显示「已还原」但实际什么都没还原，且原始备份被销毁，事后无法再还原**。
2. **只能还原一次**：第二次执行时备份已是 `{"restored":true}`，反序列化出的快照各项为 `null`，函数仍会返回 true 并提示成功，但不会再放回任何物品。
3. **货币不还原**：`currencies` 只写不读。
4. 物品栏放不下时的兜底顺序：主物品栏 → 末影箱 → 掉落在地上（并提示玩家）。
5. 还原只清掉该条 WIPE 处罚记录（`active = false`），不会影响该玩家其它处罚。

### 5. ⚠️ 离线清除（wipe 离线补执行）的时限问题

- `/wipe` 对离线玩家只写记录 + 备份（快照为空，JSON 为 `{}`），真正的清除被推迟到玩家登录时由 `PunishListener.onJoinExecuteOfflineWipe` 执行：它遍历该玩家**仍 active** 的 WIPE 记录，且只处理「备份 `dataJson` 恰好等于 `{}`」的那些，然后 `clearWipedData` 并 `deactivatePunishment`。
- 但 WIPE 记录的 `durationMs = 0`，`issue()` 算出的 `expiryTime = now`；每 200 tick（约 10 秒）一次的 `checkExpirations()` 会把它判定为过期并置为非激活。
  ⇒ **如果玩家在约 10 秒内没有上线，active 记录就消失，登录时不会再补执行清除**（备份与历史记录仍留在数据库里，可用处罚 ID 查到）。
- 建议：对离线玩家不要依赖 wipe 的延迟清除，等其上线后再执行，或直接用 `/wipe` 对在线玩家操作。

### 6. 静默标志与公告

- `authpunish` 解析并保存 `-s`，但指令内**完全没有广播**，所以 `-s` 无可见效果。
- `wipe` **不解析**任何标志：`-s` 之类会被当作作用域或理由文本（作用域解析只取第一个词）。
- 两者都不做全服公告。

### 7. 与其他插件的关系

- `authpunish` / `wipe` / `resumewipe` 只依赖 Bukkit API、Adventure `Component`、插件自身的数据库与 `CurrencyUtil`。
- 货币扣除可能间接走 **PlaceholderAPI + Kether**（当 `currency.yml` 里某货币 `type: PAPI` 且配置了 `actions.remove` 脚本时），这是本组指令唯一的外部联动点；未安装 PlaceholderAPI 时该货币余额读作 `0.0`、扣除失败。
- 与 Chemdah 无直接交互（不涉及任务/对话数据）。
- 别名 `wipe` 比较通用，若服务器上已有同名指令，建议使用 `/cttwipe`、`/cttresumewipe`。
