# 处罚指令：禁言 / 踢出 / 警告 / 封禁

> **根指令**：`/chotentech-mute`（别名 `cttmute`、`mute`）、`/chotentech-kick`（别名 `cttkick`、`kick`）、`/chotentech-warn`（别名 `cttwarn`、`warn`）、`/chotentech-ban`（别名 `cttban`、`ban`）
> **权限**：见下表；四个根指令均为 `permissionDefault = PermissionDefault.OP`，且声明 `newParser = false`
> **源码**：`Bukkit/src/main/kotlin/io/github/zzzyyylllty/chotentech/punish/PunishCommand.kt`（第 16–288 行，四个 `@CommandHeader` 对象）

## 功能概述

这四条指令是处罚系统（`punish` 包）里「下达处罚」的部分。每条指令都做同样三件事：

1. **解析目标**：`resolvePlayer()` 依次尝试「在线玩家名 → UUID（在线/离线数据库）→ 数据库玩家名 → 在线玩家忽略大小写匹配」，全都失败则回 `未找到玩家: <输入>` 并中止。
2. **写记录**：构造一条 `PunishEntry`，由 `PunishManager.issue()` 写入
   - 数据库表 `punishment_records`（SQLite/MySQL，见「备注」第 3 条）
   - 内存缓存 `PunishManager.activeCache`（运行时判定禁言/封禁/登录拦截全靠它）
   - 追加一行 JSON 到插件目录下的 `punishment_history.json`
3. **产生后果**：禁言由 `PunishListener` 拦截 `AsyncChatEvent`；踢出/封禁立即 `kick()`；封禁与 AUTH 由 `PlayerLoginEvent` 拦截；并按 `-s` 决定是否全服公告。

> 四个根指令的指令树都只有一个节点：`mainCommand { dynamic("target") { … } }`。
> 也即 **只有 `target` 一个真正的参数**，其余内容（时长、理由、`-s`/`-n` 标志）都是 `execute` 第三个参数 `argument`（剩余整串文本）里自行解析的「原始文本」。
> 因此这四个根指令**无参执行不会打印帮助树**（源码没有给 `mainCommand` 注册 `execute`，也没有 `createModernHelper()`），只会得到框架的缺参提示。

## 指令详解

### `/chotentech-mute <target> [-s] [<时长>] [<理由>]`

- **用途**：禁言一名玩家。禁言生效期间该玩家的聊天会被 `PunishListener.onChatMuteCheck` 拦截（`AsyncChatEvent` 被取消），并收到「你已被禁言！剩余时间: …」与理由提示。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `target` | 目标玩家：在线玩家名 / 玩家 UUID / 数据库中登记过的玩家名（源码 `dynamic("target")`） | 必填 | 自动补全：当前在线玩家名（`Bukkit.getOnlinePlayers().map { it.name }`） |
  | `-s` | 静默标志，可写多次。写在剩余文本最前面才生效（`parseMuteArgs` 循环剥离） | 可选 | 无（不参与补全） |
  | `<时长>` | 时长 token，如 `30m`、`7d`、`1d12h`（格式见「备注」第 1 条）；也接受 `永久`/`perm`/`permanent`/`forever`/`-1` | 可选 | 无（不参与补全） |
  | `<理由>` | 处罚理由，剩余的整段文本；可以只写「预配置理由」的前缀，由 `punishment.mute-reasons` 反查时长（见下） | 可选 | 无（不参与补全） |

- **权限**：`chotentech.command.mute`（默认 OP）。源码 `execute` 内**没有**额外 `sender.hasPermission(...)` 校验；但时长上限由 `PunishManager.getMaxDuration(sender)` 按 `punishment.duration-limits` 里的**权限键**计算（默认配置：`default` = 30 天，`chotentech.punish.vip` = 90 天，`chotentech.punish.admin` = -1 无限制）。
- **执行者要求**：玩家 / 控制台均可（`execute<CommandSender>`）。控制台执行时操作者名记为 `CONSOLE`，玩家执行时记为玩家名并附带 UUID。
- **行为说明**：
  1. 解析 `target`；失败 → `未找到玩家: <输入>` 并结束。
  2. `parseMuteArgs` 依次剥离 `-s`（静默）→ 尝试解析时长 token → 尝试 `永久` 类 token → 都不匹配则整段视为理由、时长记为 0。
  3. 若「时长 ≤ 0 且理由非空」，用 `punishment.mute-reasons` 做**前缀匹配**（忽略大小写）：命中则该条时长成为处罚时长，理由改成去掉前缀后的剩余文本（剩余为空则保留原匹配到的文字）。
  4. 若时长仍 ≤ 0 → 使用默认 **600000 ms（10 分钟）**。
  5. 用 `getMaxDuration(sender)` 裁剪超限时长，并提示 `你的权限最大允许 <X> 的禁言。已按最大时长执行。`
     （注意：永久禁言的 `durationMs` 是 `-1`，`-1 > 上限` 恒为 false，因此**永久不会被裁剪**，与 `/ban` 的写法不同。）
  6. 写入记录（`type = MUTE`），拿到 `ID`。
  7. 被处罚者在线且**非静默** → 收到 `你已被禁言！时长: <X>，理由: <Y>`。
  8. 执行者收到 `已禁言 <玩家>，时长: <X>，ID: <id>`（永久显示为 `永久`）。
  9. 非静默 → `Bukkit.broadcast` 全服公告 `…已被管理员 <执行者> 禁言，时长: <X>`。
- **示例**：
  - `/mute Steve 30m 刷屏` → 禁言 30 分钟，理由「刷屏」。
  - `/mute Steve 7d 广告/宣传` → 禁言 7 天（时长 token 优先于预配置理由）。
  - `/mute Steve -s 刷屏/恶意灌水` → 静默；时长取 `punishment.mute-reasons` 中该条配置的时长（默认配置为 `10m`）。
  - `/mute Steve 永久 严重违规` → 永久禁言。

### `/chotentech-kick <target> [-s] [<理由>]`

- **用途**：把玩家踢下线，同时留一条 `KICK` 记录（用于历史/审计）。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `target` | 目标玩家（在线玩家名 / UUID / 数据库玩家名） | 必填 | 自动补全：在线玩家名 |
  | `-s` | 静默标志（不广播），写在剩余文本最前面才生效 | 可选 | 无 |
  | `<理由>` | 踢出理由，剩余整段文本；留空时用默认值 `你已被踢出服务器` | 可选 | 无 |

- **权限**：`chotentech.command.kick`（默认 OP）；无运行期额外校验。
- **执行者要求**：玩家 / 控制台均可。**但真正被踢的只有在线的目标玩家**（源码用 `getOnlinePlayerByName` 取玩家，取不到就只写记录）。
- **行为说明**：
  1. `parseKickArgs` 只剥离 `-s`，**其余全部当理由**（踢出指令没有时长概念，`durationMs = 0`）。
  2. 理由为空 → `你已被踢出服务器`。
  3. 写入 `type = KICK` 记录（时长为 0）。
  4. 目标在线 → `player.kick(Component.text(reason))`；离线 → 不踢，但记录照样写入。
  5. 执行者收到 `已踢出 <玩家>，理由: <理由>`；非静默时全服公告 `…已被管理员 <执行者> 踢出服务器`。
- **示例**：`/kick Steve 挂机`、`/cttkick Steve -s 维护`。

### `/chotentech-warn <target> [<理由>]`

- **用途**：给玩家记一条警告，并告诉他当前累计警告条数。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `target` | 目标玩家（在线玩家名 / UUID / 数据库玩家名） | 必填 | 自动补全：在线玩家名 |
  | `<理由>` | 警告理由，剩余整段文本；留空时用默认值 `违反服务器规则` | 可选 | 无 |

- **权限**：`chotentech.command.warn`（默认 OP）；无运行期额外校验。
- **执行者要求**：玩家 / 控制台均可。
- **行为说明**：
  1. `parseWarnArgs` 只做一件事：`reason = argument.trim()`。**警告没有 `-s` 静默标志**——写 `-s` 会被当成理由文字的一部分。
  2. 理由为空 → `违反服务器规则`。
  3. 写入 `type = WARN` 记录（`durationMs = 0`），并立刻调用 `PunishManager.getWarnCount(uuid)` 统计该玩家**缓存中仍 active** 的警告条数。
  4. 执行者收到 `已警告 <玩家>，累计警告: <N>，ID: <id>`。
  5. 目标在线 → 收到 `你已被警告！理由: <理由> (累计 N 次)`（**不受静默影响**，因为警告没有静默概念）。
  6. **没有全服公告**。
- **示例**：`/warn Steve 刷屏`, `/cttwarn Steve`.
- **注意**：`config.yml` 里的 `punishment.max-warn-before-ban`（默认 5）会被读进 `PunishManager.maxWarnBeforeBan`，但**源码中没有任何地方使用它**——「累计警告自动封禁」在当前版本未实现。详见「备注」第 6 条（警告记录会在约 10 秒后被到期扫描清掉）。

### `/chotentech-ban <target> [-n] [-s] [<时长>] [<理由>]`

- **用途**：封禁玩家（`PunishType.BAN`，显示名「限制登录」）。被记录在 `activeCache` 中的 BAN/AUTH 会在 `PlayerLoginEvent` 阶段直接 `disallow`，玩家无法进服。
  默认情况下封禁会**顺带签发一条永久 AUTH（身份验证）记录**，玩家必须联系管理员解除。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `target` | 目标玩家（在线玩家名 / UUID / 数据库玩家名） | 必填 | 自动补全：在线玩家名 |
  | `-n` | 跳过 AUTH：不再自动签发 AUTH 记录（写入 `meta.skipAuth = "true"`）。**必须写在 `-s` 之前** | 可选 | 无 |
  | `-s` | 静默标志（不广播）。**必须在 `-n` 之后** | 可选 | 无 |
  | `<时长>` | 时长 token 或 `永久`/`perm`/`permanent`/`forever`/`-1`；**不给则为永久** | 可选 | 无 |
  | `<理由>` | 封禁理由，剩余整段文本；留空时用默认值 `违反服务器规则` | 可选 | 无 |

- **权限**：`chotentech.command.ban`（默认 OP）。运行期无额外 `hasPermission` 校验；时长上限同样来自 `punishment.duration-limits` 的权限键。
- **执行者要求**：玩家 / 控制台均可。
- **行为说明**：
  1. `parseBanArgs` 的解析顺序固定：先循环剥离 `-n`（可重复）→ 再循环剥离 `-s`（可重复）→ 剩下的文本做「永久 / 时长」解析，再剩下的部分作为理由。
     因为 `-n` 的剥离循环在前，**`/ban X -s -n 1d 理由` 里的 `-n` 不会被识别**，会被当成理由文字（并导致时长解析失败 → 变成永久封禁）。正确写法是 `/ban X -n -s 1d 理由`。
  2. 时长 ≤ 0（未给或解析失败）→ `durationMs = -1`（永久）。
  3. 时长上限裁剪：`maxMs != -1L && durationMs != -1L && durationMs > maxMs` 时按上限执行并提示 `你的权限最大允许 <X> 的封禁。已按最大时长执行。`——**永久封禁不参与裁剪**。
  4. 写入 `type = BAN` 记录，拿到 `ID`。
  5. `PunishManager.issue()` 内部：若该 BAN 没有 `meta["skipAuth"] = "true"`，会**递归签发一条 AUTH 记录**（`durationMs = -1`、永久、`meta.parentBanId = <BAN 的 ID>`）。所以一次 `/ban`（不带 `-n`）实际会写入两条记录，占用两个 `ID`。
  6. 执行者收到 `已封禁 <玩家>，时长: <X>，ID: <id>`；未带 `-n` 时追加后缀 ` (附带AUTH验证)`。
  7. 目标在线 → 立即被踢，踢出消息为多行：
     `你已被封禁！` / `理由: <理由>` / `时长: <X>` / （未带 `-n` 时追加）`请主动联系管理员解除AUTH验证`。
  8. 非静默 → 全服公告 `…已被管理员 <执行者> 封禁，时长: <X>`。
  9. 之后目标再登录时，`PunishListener.onLoginBanCheck` 仍会拦截，并额外显示 `解封时间: <yyyy-MM-dd HH:mm:ss>`（永久封禁不显示该行）。
- **示例**：
  - `/ban Steve 7d 使用外挂` → 封禁 7 天，并自动附带永久 AUTH 验证（两条记录）。
  - `/ban Steve -n 30d 使用外挂` → 封禁 30 天，**不**附带 AUTH。
  - `/ban Steve -n -s 永久 严重违规` → 永久封禁、无 AUTH、不广播。

## 备注 / 注意事项

### 1. 时长格式（`PunishUtil.parseDurationTokens` / `parsePermanentAndDuration`）

解析用的正则：`^(\d+)\s*(mo|[wdhMs]|m(?![oO]))`，单位换算：

| 单位 | 含义 | 毫秒 |
|---|---|---|
| `s` | 秒 | `value * 1000` |
| `m` | 分钟 | `value * 60 000` |
| `h` | 小时 | `value * 3 600 000` |
| `d` | 天 | `value * 86 400 000` |
| `w` | 周（7 天） | `value * 604 800 000` |
| `mo` / `M` | 月（按 30 天算） | `value * 2 592 000 000` |

- 数字与单位之间的空格可有可无（`30m`、`30 m` 均可）。
- 可以**串联多段**：`1d12h`、`1d 12h 30m`（`parseDurationTokens` 循环匹配，累加直到遇到第一个不匹配的字符）。
- 大小写敏感：小写 `m` = 分钟，大写 `M` = 月（30 天）。
- 永久写法：`永久`、`perm`、`permanent`、`forever`、`-1`（`ignoreCase`，必须位于剩余文本开头，且后面是空白或结束）。
- 无法解析为时长的剩余文本原样变成「理由」，因此理由可以中文、可以带空格，不需要引号。

### 2. 各指令的时长默认值（源码硬编码）

| 指令 | 未给时长时 |
|---|---|
| `/mute` | 先尝试预配置理由反查；还不行 → **600000 ms（10 分钟）** |
| `/kick` | 无时长概念（`durationMs = 0`） |
| `/warn` | 无时长概念（`durationMs = 0`） |
| `/ban` | **永久**（`durationMs = -1`） |

### 3. 数据存储位置

- **数据库**：由 `PunishManager` 通过 TabooLib `db("config.yml", "database", "chotentech.db")` 取得连接（连接参数来自 `config.yml` 的 `database` 段，内置默认 `enable: false` 即 SQLite、`true` 为 MySQL）。处罚记录表名 `punishment_records`（`@TableName`），清除数据的备份表名 `wipe_backups`。
- **内存缓存**：`PunishManager.activeCache`（`uuid -> List<PunishEntry>`）。禁言拦截、登录拦截、警告计数全部读这份缓存。插件启动（`LifeCycle.ACTIVE`）时 `reloadActiveCache()` 从表里回填 `active = true` 且**未过期**的记录，所以重启后禁言/封禁/AUTH 仍然有效。
- **历史文件**：每次 `issue()` 都会把该条记录以单行 JSON 追加到插件数据目录的 `punishment_history.json`（`writeHistory`）。`getPlayerPunishmentHistory` 也读这个文件。
- **到期扫描**：`submit(period = 200)` 启动的定时任务每 **200 tick ≈ 10 秒** 调一次 `checkExpirations()`，把过期记录置为非激活（禁言、AUTH 到期时会给在线玩家发提示）。

### 4. 静默（`-s`）的实际效果

| 指令 | `-s` 抑制的内容 |
|---|---|
| `/mute` | ① 全服广播 ② 给被处罚者的私聊通知 |
| `/kick` | 全服广播（被踢者仍会看到踢出理由） |
| `/ban` | 全服广播（被踢者仍会看到封禁理由） |
| `/warn` | **不支持**，写了也只是理由的一部分 |

### 5. 权限与时长上限

- 命令权限只有根指令上的一个：`chotentech.command.mute` / `.kick` / `.warn` / `.ban`，默认 OP。
- 另有「按权限给不同最大处罚时长」的机制：`config.yml` → `punishment.duration-limits`，键名就是**权限节点**，`default` 为基线值（单位毫秒）：

  ```yaml
  punishment:
    duration-limits:
      default: 2592000000            # 30天
      chotentech.punish.vip: 7776000000   # 90天
      chotentech.punish.admin: -1    # -1 = 无限制
  ```
  `getMaxDuration` 会取「基线」与「执行者拥有的所有键」中最宽松的一个；任一键为 `-1` 就直接返回无限制。

### 6. ⚠️ 已知源码行为（管理员需知）

1. **警告计数会很快归零**：`/warn` 写入的 `durationMs = 0`，而 `issue()` 里 `expiryTime = now + durationMs = now`。每 10 秒的 `checkExpirations()` 会把它判定为已过期并 `deactivatePunishment`，随后 `getWarnCount` 就统计不到它了。因此「累计警告」实际只在签发后约 10 秒内准确；`max-warn-before-ban` 也没有任何调用点。
2. **`永久` + 预配置理由会被理由时长覆盖**：`/mute Steve 永久 刷屏/恶意灌水` 中，`parseMuteArgs` 得到 `durationMs = -1`，随后「时长 ≤ 0 且理由非空」的分支会命中 `mute-reasons` 前缀并把时长改写成该条的 10 分钟。要永久禁言，理由不要以预配置理由开头。
3. **永久禁言不受时长上限约束**（`/ban` 的裁剪条件额外判断了 `durationMs != -1L`，`/mute` 没有）。
4. **`/ban` 的 `-n` 必须写在 `-s` 前面**，否则 `-n` 会被当作理由文本处理。
5. **踢出/警告/清除数据记录立刻「过期」**：这三类的 `durationMs = 0`，`isExpired` 在签发瞬间就为 true（不影响 kick 本身，因为踢出是即时动作）。
6. **控制台执行者名统一记为 `CONSOLE`**；玩家执行时记录玩家名与 UUID。

### 7. 与原版/其他插件的关系

- `mute` / `kick` / `ban` / `warn` 这类通用别名可能与服务器上其它管理插件（如 Essentials 系列）的同名指令冲突，实际生效者取决于注册顺序；不确定时请使用带前缀的 `/cttmute`、`/cttkick`、`/cttban`、`/cttwarn` 或完整名。
- 本组指令不依赖 Chemdah 等外部插件：只用到 Bukkit API、Adventure `Component`（踢出消息）以及插件自身的数据库模块。清理类指令涉及的货币模块见 `02-处罚指令-授权与清除数据.md`。
- 被踢/被封的提示文案由插件内 `toComponent` 渲染，支持 `<#RRGGBB>` 颜色标记；`kick()` 使用的是 Adventure `Component.text(...)`，即原样纯文本（不解析 MiniMessage 颜色）。
