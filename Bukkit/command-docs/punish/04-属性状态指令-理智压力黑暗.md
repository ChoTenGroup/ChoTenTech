# 属性状态指令：理智 / 压力 / 黑暗

> **根指令**：`/chotentech-sanity`（别名 `cttsanity`、`sanity`）、`/chotentech-stress`（别名 `cttstress`、`stress`）、`/chotentech-darkness`（别名 `cttdarkness`、`darkness`）
> **权限**：见下表；三个根指令均为 `permissionDefault = PermissionDefault.OP`，且声明 `newParser = true`
> **源码**：`Bukkit/src/main/kotlin/io/github/zzzyyylllty/chotentech/punish/StatCommands.kt`（第 15–525 行，三个 `@CommandHeader` 对象）

## 功能概述

这三条指令是玩家**状态数值**（精神值 / 压力 / 阴暗值）的管理工具，虽然放在 `punish` 包里，但本身不是处罚——它们直接读写在线玩家 `PlayerData` 里的字段：

| 数值 | `PlayerData` 字段 | 默认值 | 上限 |
|---|---|---|---|
| 精神值（理智） | `sanity` | `40.0` | `effectiveMaxSanity` |
| 精神值上限 | `maxSanity` | `100.0` | 无硬上限（由属性 `max_sanity` 优先决定实际生效值） |
| 精神恢复 | 属性修饰符 `sanity_regeneration` | `0.0` | 无 |
| 压力 | `stress` | `0.0` | **硬编码 100.0** |
| 阴暗值 | `darkness` | `15.0` | `effectiveMaxDarkness` |
| 阴暗值上限 | `maxDarkness` | `100.0` | 无硬上限（由属性 `max_darkness` 优先决定实际生效值） |

三条指令的骨架完全一致（`SanityCommand` / `StressCommand` / `DarknessCommand` 三个对象）：

- `@CommandBody val main = mainCommand { createModernHelper() }` —— **无参执行时打印指令树**，并按执行者权限过滤子指令。
- 其余每个 `@CommandBody val xxx = subCommand { player("target") { … } }` —— 属性名即字面量子指令（如 `add` → `/sanity add`）。
- 每个子指令都以 `player("target") { … }` 开头，因此**目标玩家必须在线**（解析不到时统一回 `玩家不在线`）。
- 数值参数统一叫 `amount`（`dynamic("amount")`，`toDoubleOrNull` 解析，Tab 补全固定给 `100`）；解析失败时打印各自的用法提示并结束。
- 所有输出数值都用 `"%.1f"` 格式化（保留一位小数）。
- 指令内**不调用任何保存方法**，改的是内存中的 `PlayerData`（`playerDataMap` 缓存），随插件常规数据/档案保存流程落库。

## 指令总览

| 根指令 | 别名 | 说明 | 权限 | 默认 |
|---|---|---|---|---|
| `chotentech-sanity` | `cttsanity`、`sanity` | 精神值（理智）及其上限、恢复速度 | `chotentech.command.sanity` | OP |
| `chotentech-stress` | `cttstress`、`stress` | 压力值（上限固定 100） | `chotentech.command.stress` | OP |
| `chotentech-darkness` | `cttdarkness`、`darkness` | 阴暗值及其上限 | `chotentech.command.darkness` | OP |

各根指令的子指令（字面量）清单：

| 根指令 | 子指令 |
|---|---|
| `/sanity` | `add`、`set`、`reset`、`get`、`full`、`maxadd`、`maxset`、`maxreset`、`maxget`、`regenadd`、`regenset`、`regenreset`、`regenget`（共 **13** 个） |
| `/stress` | `add`、`set`、`reset`、`get`（共 **4** 个） |
| `/darkness` | `add`、`set`、`reset`、`get`、`full`、`maxadd`、`maxset`、`maxreset`、`maxget`（共 **9** 个） |

> 每个子指令的参数形状只有两种：`<target> <amount>` 或 `<target>`（无 `amount`）。
> 源码里 `ChoTenDataHelper` 还有 `removeSanity` / `removeMaxSanity` / `removeStress` / `removeDarkness` / `removeMaxDarkness` / `removeSanityRegeneration` 等方法，但**没有对应的指令**。

## 指令详解

### `/chotentech-sanity`（`/cttsanity`、`/sanity`）

- **无参**：`createModernHelper()` 打印 `/chotentech-sanity` 的指令树（按执行者权限过滤），可当作运行时帮助。
- **权限**：`chotentech.command.sanity`（默认 OP）。子指令源码未单独声明 `permission`，`execute` 内也没有 `hasPermission` 校验。
- **执行者要求**：玩家 / 控制台均可（`execute<CommandSender>`），但**目标玩家必须在线**。

#### `/sanity add <target> <amount>`

- **用途**：增加（可为负数，即减少）目标玩家的精神值。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `target` | 目标玩家（源码 `player("target")`） | 必填 | 自动补全：在线玩家名 |
  | `amount` | 双精度数值，可负 | 必填 | 补全示例 `100`；非法数值时提示 `用法: /sanity add <玩家> <数量>` |

- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线（否则 `玩家不在线`）。
- **行为说明**：`sanity = clamp(sanity + amount, 0.0, effectiveMaxSanity)`；回复 `已为 <玩家> 增加 <amount> 精神值，当前: <值>`。
- **示例**：`/sanity add Steve 20`、`/cttsanity add Steve -30`（降低 30）。

#### `/sanity set <target> <amount>`

- **用途**：把精神值直接设为指定值。
- **参数**：`target`（在线玩家）/ `amount`（双精度，必填，补全 `100`；非法时提示 `用法: /sanity set <玩家> <数量>`）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`sanity = clamp(amount, 0.0, effectiveMaxSanity)`（超出上限会被压到上限）；回复 `已将 <玩家> 的精神值设为 <值>`（显示的是写入后的实际值）。
- **示例**：`/sanity set Steve 100`。

#### `/sanity reset <target>`

- **用途**：把精神值重置为**配置默认值**。
- **参数**：

  | 参数 | 类型/含义 | 是否必填 | 可选值/自动补全 |
  |---|---|---|---|
  | `target` | 目标玩家 | 必填 | 自动补全：在线玩家名 |

- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`sanity = clamp(config.yml 的 default.sanity（默认 40.0）, 0.0, effectiveMaxSanity)`；回复 `已重置 <玩家> 的精神值，当前: <值>`。
- **示例**：`/sanity reset Steve`。

#### `/sanity get <target>`

- **用途**：查询精神值与当前上限。
- **参数**：`target`（在线玩家）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：输出 `<玩家> 精神值: <sanity> / <effectiveMaxSanity>`，只读。
- **示例**：`/sanity get Steve`。

#### `/sanity full <target>`

- **用途**：把精神值直接填满到上限。
- **参数**：`target`（在线玩家）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`sanity = effectiveMaxSanity`；回复 `已回满 <玩家> 的精神值`（不回显数值）。
- **示例**：`/sanity full Steve`。

#### `/sanity maxadd <target> <amount>`

- **用途**：调整精神值**上限**（`maxSanity` 字段）。
- **参数**：`target` / `amount`（双精度，可负，必填，补全 `100`；非法时提示 `用法: /sanity maxadd <玩家> <数量>`）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`maxSanity = max(maxSanity + amount, 0.0)`；回复里「当前」显示的是 `effectiveMaxSanity`（即属性 `max_sanity` 生效值，见「备注」第 3 条）。
- **示例**：`/sanity maxadd Steve 50`。

#### `/sanity maxset <target> <amount>`

- **用途**：把精神值上限设为指定值。
- **参数**：`target` / `amount`（双精度，必填，补全 `100`；非法时提示 `用法: /sanity maxset <玩家> <数量>`）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`maxSanity = max(amount, 0.0)`；回复显示 `effectiveMaxSanity`。
- **示例**：`/sanity maxset Steve 150`。

#### `/sanity maxreset <target>`

- **用途**：把精神值上限重置为配置默认值。
- **参数**：`target`（在线玩家）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`maxSanity = max(config.yml 的 default.max-sanity（默认 100.0）, 0.0)`；回复显示 `effectiveMaxSanity`。
- **示例**：`/sanity maxreset Steve`。

#### `/sanity maxget <target>`

- **用途**：查询精神值上限。
- **参数**：`target`（在线玩家）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：只读，输出 `<玩家> 最大精神值: <effectiveMaxSanity>`。
- **示例**：`/sanity maxget Steve`。

#### `/sanity regenadd <target> <amount>`

- **用途**：调整精神值**恢复速度**。实现方式是往玩家身上挂/改一个属性修饰符 `sanity_regeneration`（`AttributeModifier`，固定 UUID `00000000-0000-0000-0000-000000000001`，`ModifierType.ADD`，`ModifierSource.OTHER`），而不是改 `PlayerData` 字段。
- **参数**：`target` / `amount`（双精度，可负，必填，补全 `100`；非法时提示 `用法: /sanity regenadd <玩家> <数量>`）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：读取现有修饰符值 → `setSanityRegenModifier(max(current + amount, 0.0))`：先按固定 UUID 移除旧修饰符，值 > 0 时重新添加（值 ≤ 0 就只剩移除效果）；回复 `已为 <玩家> 增加 <amount> 精神恢复，当前: <data.sanityRegeneration>`。
- **示例**：`/sanity regenadd Steve 5`、`/sanity regenadd Steve -5`。

#### `/sanity regenset <target> <amount>`

- **用途**：把精神值恢复速度设为指定值。
- **参数**：`target` / `amount`（双精度，必填，补全 `100`；非法时提示 `用法: /sanity regenset <玩家> <数量>`）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`setSanityRegenModifier(max(amount, 0.0))`，设成 `0` 等价于移除修饰符；回复 `已将 <玩家> 的精神恢复设为 <值>`。
- **示例**：`/sanity regenset Steve 10`。

#### `/sanity regenreset <target>`

- **用途**：把精神值恢复速度清零（移除修饰符）。
- **参数**：`target`（在线玩家）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`setSanityRegenModifier(0.0)` → 移除该 UUID 的修饰符（不再重新添加）；回复 `已重置 <玩家> 的精神恢复，当前: <值>`（通常显示 `0.0`，或回落成配置 `default.sanity-regen`）。
- **示例**：`/sanity regenreset Steve`。

#### `/sanity regenget <target>`

- **用途**：查询精神值恢复速度。
- **参数**：`target`（在线玩家）。
- **权限**：`chotentech.command.sanity`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：只读，输出 `<玩家> 精神恢复: <data.sanityRegeneration>`（属性 `sanity_regeneration` 的值，`> 0` 时生效，否则回落配置 `default.sanity-regen`）。
- **示例**：`/sanity regenget Steve`。

### `/chotentech-stress`（`/cttstress`、`/stress`）

- **行为说明**：`stress = clamp(stress + amount, 0.0, 100.0)`；回复 `已为 <玩家> 增加 <amount> 压力，当前: <值>`。

#### `/stress set <target> <amount>`

- **用途**：把压力设为指定值。
- **参数**：`target` / `amount`（双精度，必填，补全 `100`；非法时提示 `用法: /stress set <玩家> <数量>`）。
- **权限**：`chotentech.command.stress`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`stress = clamp(amount, 0.0, 100.0)`（>100 会被压到 100）；回复 `已将 <玩家> 的压力设为 <值>`。
- **示例**：`/stress set Steve 80`。

#### `/stress reset <target>`

- **用途**：把压力重置为配置默认值。
- **参数**：`target`（在线玩家）。
- **权限**：`chotentech.command.stress`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：`stress = clamp(config.yml 的 default.stress, 0.0, 100.0)`。**注意内置 `config.yml` 没有 `default.stress` 键**，因此回落到代码默认值 `0.0`；回复 `已重置 <玩家> 的压力，当前: <值>`。
- **示例**：`/stress reset Steve`。

#### `/stress get <target>`

- **用途**：查询压力。

- **权限**：`chotentech.command.stress`。
- **执行者要求**：玩家 / 控制台均可；目标需在线。
- **行为说明**：只读，输出 `<玩家> 压力: <stress> / 100.0`。
- **示例**：`/stress get Steve`。

- **行为说明**：只读，输出 `<玩家> 最大阴暗值: <effectiveMaxDarkness>`。
- **示例**：`/darkness maxget Steve`。

## 备注 / 注意事项

### 1. 参数约定

- 玩家参数统一是 `player("target")`：Tab 补全为在线玩家名；解析不到（或玩家不在线）时 `context.player("target").castSafely<Player>()` 为 null，指令统一回 `玩家不在线` 并结束——**这三条指令不支持离线玩家**。
- 数值参数统一是 `dynamic("amount")`：用 `toDoubleOrNull()` 解析，因此可以写小数（`12.5`）与负数（`-10`，对 `add` 系列即减少）；解析失败时打印对应子指令的 `用法: /<根指令> <子指令> <玩家> <数量>` 提示。补全固定给 `100`。
- 执行者（sender）可以是控制台，被操作的目标必须是玩家。

### 2. 数值钳制（源码硬编码）

| 指令族 | 钳制规则 |
|---|---|
| `sanity add` / `sanity set` / `sanity reset` / `sanity full` | `0.0 ~ effectiveMaxSanity` |
| `sanity maxadd` / `maxset` / `maxreset` | 下限 0，无上限 |
| `sanity regen*` | 下限 0，无上限（值 ≤ 0 时移除修饰符） |
| `stress add` / `set` / `reset` | `0.0 ~ 100.0`（硬编码，不可配置） |
| `darkness add` / `set` / `reset` / `full` | `0.0 ~ effectiveMaxDarkness` |
| `darkness maxadd` / `maxset` / `maxreset` | 下限 0，无上限 |

### 3. 「有效上限」来自属性系统（容易误解的地方）

`PlayerData.effectiveMaxSanity` / `effectiveMaxDarkness` / `sanityRegeneration` 都走 `attrMax(属性ID, 回落值)`：

- 玩家在线且 `AttributeManager.getAttributeValue(player, 属性ID) > 0` → **用属性值**；
- 否则 → 用 `PlayerData` 里的字段（`maxSanity` / `maxDarkness` / 配置 `default.sanity-regen`）。

对应关系：`effectiveMaxSanity ← max_sanity`、`effectiveMaxDarkness ← max_darkness`、`sanityRegeneration ← sanity_regeneration`。

因此 `maxadd` / `maxset` / `maxreset` 改的是**字段**，但回复与 `maxget` 显示的是**生效值**——如果该玩家身上有 `max_sanity` / `max_darkness` 属性加成，你改完可能看不到数字变化。同理 `add`/`set`/`full` 能填到多高，取决于属性生效后的上限。

### 4. 精神恢复（`regen*`）的实现细节

- 不是 `PlayerData` 字段，而是 `AttributeManager` 上的修饰符：`attributeId = "sanity_regeneration"`、`ModifierType.ADD`、`ModifierSource.OTHER`、固定 UUID `00000000-0000-0000-0000-000000000001`。
- 每次设置都先 `removeModifierByUuid` 再按需 `addModifier`，所以**同一玩家只会有一条**该 UUID 的修饰符（手工重复叠加不会累积）。
- `regenreset` 等价于 `regenset 0`；值为 0 时修饰符被移除。
- `regenget` 显示的是属性值；若属性值为 0/不存在，则回落 `config.yml` 的 `default.sanity-regen`（内置默认 `0.0`）。

### 5. 配置项一览（`config.yml`）

```yaml
default:
  sanity: 40.0          # /sanity reset 的目标值
  max-sanity: 100.0     # /sanity maxreset 的目标值
  darkness: 15.0        # /darkness reset 的目标值
  max-darkness: 100.0   # /darkness maxreset 的目标值
  sanity-regen: 0.0     # regenget 的回落值
# 注意：没有 default.stress，/stress reset 会回落到代码默认 0.0
```

`PlayerData` 的出厂默认值与之对应：`sanity = 40.0`、`maxSanity = 100.0`、`stress = 0.0`、`darkness = 15.0`、`maxDarkness = 100.0`。

### 6. 数据存储位置

- 全部改动都写在**内存**里的 `PlayerData`（`playerDataMap[uuid]`，由 `ChoTenDataHelper(player)` 取得；缓存里没有时 `DataManager.initData(player)` 初始化）。
- 指令内没有任何显式保存调用，落库依赖插件常规的玩家数据/档案保存流程（退出、档案切换等）。
- 精神值/压力/阴暗值**不是**共享字段：`ProfileManager.stripSharedFields` 只剥离 `tape` / `ltoken` / `ptoken` / `achievements` / `cosmetics` 这五项为「全档案共享」，其余字段（含 `sanity` / `maxSanity` / `stress` / `darkness` / `maxDarkness`）随**当前档案**一起保存。也就是说这三条指令改的是玩家「当前所在档案」的数值，切换档案会看到另一套数值。
- `regen*` 的修饰符由 `AttributeManager` 的玩家持久化数据承载，与上面的 `PlayerData` 字段分开存储。

### 7. 与处罚系统的关系

- 这三条指令只是「数值管理」，不会写入 `punishment_records`，也不会产生处罚记录、不广播、不需要理由/时长参数。
- 与处罚系统的交集仅在于包位置（都在 `punish` 包）以及「精神值/阴暗值低到阈值时的游戏机制」由别处逻辑处理（`config.yml` 里有 `sanity-drain-threshold: 80.0`、`sanity-drain-amount: 0.2` 之类的调参项）。
- 无 Chemdah 等外部插件依赖。

### 8. 其它

- 三个根指令都使用 `newParser = true`（与 `punish` 包里 `PunishCommand.kt` / `UnpunishCommand.kt` 的 `newParser = false` 不同）。
- `createModernHelper()` 会按执行者权限过滤要显示的节点，所以 OP 看到的指令树最完整；控制台执行无参指令同样能看到全部节点。
- 别名 `sanity` / `stress` / `darkness` 比较通用，若服务器上已有同名指令，请使用 `/cttsanity`、`/cttstress`、`/cttdarkness` 或完整名。
